# План поэтапной миграции фронтенда

## Цель и критерий готовности

Перевести клиент с монолитного `src/newFrontApp.js` (ручной `innerHTML`, 67 глобальных `window.__ba_*`, общий мутируемый `state`) на React 19 + TypeScript, **не меняя внешний вид**.

«1 в 1» проверяется автоматически: каждый перенесённый экран обязан попиксельно совпасть с эталонными скриншотами, снятыми с legacy-клиента. Отличия допустимы только как явно записанное решение в этом документе.

## Целевой стек

| Задача | Выбор |
| --- | --- |
| UI | React 19 + TypeScript, Vite |
| Серверные данные | TanStack Query |
| UI-состояние | Zustand (стек экранов, вкладки, модалки, черновики) |
| Навигация | собственный стек экранов в store, как `go`/`back` сейчас; hash-роутинг запрещён — Telegram передаёт `initData` в hash |
| Типы API | `@nestjs/swagger` → `openapi-typescript` (после стабилизации NestJS-контрактов) |
| Моки для dev/unit | MSW |
| Стили | текущие CSS без изменений + `clsx`; без UI-китов (VKUI, Telegram UI) и без Tailwind на этапе переноса |
| Платформа | собственный адаптер над Telegram SDK и `@vkontakte/vk-bridge` из npm |
| Тесты | Playwright (визуальная регрессия), Vitest + Testing Library |

## Принцип безопасности

Legacy-клиент (`src/`, `index.html`, корневые `vite.config.js` и `package.json`) **не изменяется** в ходе миграции и остаётся production-клиентом до явного переключения. Новый клиент живёт в отдельном пакете `frontend/` со своими зависимостями, сборкой и dev-портом — по аналогии с `backend/`. Откат на любом этапе — не переключать или переключить обратно, без правок кода.

## Этапы

### 0. Визуальный baseline legacy-клиента — завершён

- `frontend/visual/`: Playwright снимает production-сборку legacy-клиента. Она собирается отдельным конфигом из `frontend/visual/` во временный каталог; корневой `vite.config.js` и `dist/` не затрагиваются.
- Данные отдаёт настоящий legacy API на временной копии `bot/` и отдельной SQLite с детерминированным сидом. Ручные фикстуры не пишутся: ответы всегда совпадают с реальным контрактом.
- Вход — через web-session каждой роли (production-путь, без dev-only `?preview`).
- Мутирующие запросы (`POST`/`PATCH`) перехватываются в браузере, поэтому тесты не меняют БД и не зависят от порядка.
- Внешние скрипты (Telegram SDK, vk-bridge) заглушены, шрифты Google Fonts отдаются локально из `@fontsource`, анимации отключены — снимки воспроизводимы офлайн.
- Даты сида лежат в будущем (2030 год), чтобы retention-очистка legacy API не меняла данные со временем.
- Матрица: экраны ролей × светлая/тёмная тема × 390×844 и 360×800 — 24 сценария, 228 эталонов.
- Сравнение без допусков (`threshold: 0`, `maxDiffPixels: 0`); стабильность проверена 5 повторами (480/480), чувствительность — сдвигом на 1px, сменой оттенка, интервала и радиуса.
- Запуск: `npm --prefix frontend run visual:test`; устройство стенда описано в `frontend/README.md`.

### 1. Каркас нового клиента в `frontend/`

- React 19 + TypeScript + Vite, собственный `package.json`, dev-порт и `dist`.
- Подключены те же CSS-файлы, что у legacy (импорт без копирования и без правок), платформенный адаптер, API-клиент, store и стек экранов.
- Тот же визуальный набор тестов запускается против нового клиента; непортированные экраны помечаются как ожидаемо падающие.

### 2. Перенос экранов по одному

Порядок: loading/error → гость → вход и регистрация → ученик → ДЗ (новое, просмотр, правка) → преподаватель → администратор → чат.

Для каждого экрана: разметка переносится буквально (классы и inline-стили), данные — через TanStack Query; экран принят, когда его снимки совпадают с baseline legacy.

### 3. Параллельный запуск

- Новый клиент публикуется по отдельному адресу (тестовый путь или тестовый бот/VK-приложение) и работает с тем же API.
- Ручной прогон ролей в Telegram и VK WebView; production по-прежнему обслуживает legacy.

### 4. Переключение и очистка

- Переключение — смена каталога сборки в nginx / URL мини-приложения; откат — обратная смена.
- Legacy `src/` удаляется только после периода стабильной работы и отдельного решения. После этого можно выносить inline-стили в CSS Modules под защитой скриншотов.

## Дефекты legacy, найденные при снятии baseline

Эталоны фиксируют их как есть. При переносе соответствующего экрана нужно решить: повторить 1 в 1 или исправить с переснятием эталона.

- **Гостевая страница ученика** показывает статичные `/demo-homework-*.png` вместо реальных работ и публично выводит работы «На проверке» (связано с `SEC-001`).
- **Чекбоксы назначения преподавателей в светлой теме** выглядят отмеченными, хотя `checked === false`; в тёмной теме отображаются верно.
- **Фото в чате** отображается подписью «Файл» без превью.

## Известные расхождения, требующие решения

- Анимация появления (`.fi`) сейчас проигрывается при каждой полной перерисовке; в React она будет только при монтировании экрана.
- Фокус и прокрутка сейчас сбрасываются при каждом `render()`; в React сохранятся.
- Скриншоты Chromium не заменяют ручной прогон в Telegram и VK WebView (safe-area, BackButton, тема).
