# Решения по поведению при миграции

Этот файл отделяет совместимость от исправления дефектов. Нельзя случайно закреплять небезопасное legacy-поведение как новый контракт.

## Подтверждённая стратегия

- Внешние URL и форма ответов сохраняются на первом этапе.
- NestJS и Prisma сначала работают с существующей SQLite.
- Переход SQLite → PostgreSQL выполняется отдельным этапом после отключения прямых записей Fastify и Telegram-бота.
- Перенос выполняется по одному маршруту, но бизнес-операция реализуется единым use case для HTTP и бота.
- Новые маршруты не получают прямой доступ к Prisma из controller.

## Дефекты, которые нельзя переносить как норму

| Код | Legacy-поведение | Целевое решение | Состояние |
| --- | --- | --- | --- |
| SEC-001 | Публичное портфолио возвращает работы во всех статусах; файловые URL проверяют ученика, но не `approved` работы | Публичны только одобренные работы и их вложения | В NestJS исправлены список, профиль и оба файловых маршрута; legacy остаётся уязвим до переключения routing |
| SEC-002 | Преподаватель видит чаты всех активных учеников | Доступ только к назначенным через `student_teachers`; администратор видит все | требует отдельного исправления |
| SEC-003 | Снятие роли преподавателя удаляет `teachers` и каскадно исторические проверки | Удалять роль и текущие назначения, сохраняя teacher-профиль и исторические проверки; отсутствие роли означает деактивацию | исправлено в Nest AdminModule; legacy остаётся разрушительным до переключения routing |
| SEC-004 | Четырёхзначный VK-код не имеет rate limit и счётчика попыток | Более сильный токен либо строгие лимиты и блокировка перебора | требует решения AuthModule |
| AUTH-001 | Production может работать с `TG_WEBAPP_AUTH=optional` | Production fail-fast, если режим не `strict` | до cutover AuthModule |
| AUTH-002 | Клиент передаёт `telegram_id` как часть каждого запроса | Личность берётся из проверенного credential; поле временно принимается только для совместимости | реализовано для Nest `/api/session`, showcase, notifications, `/api/student/homeworks`, авторизованных аватаров и файлов работы с вложениями |
| DATA-001 | `users.role` и `user_roles` дублируют роли | Единственный источник истины — relation ролей | после Prisma baseline |
| DATA-002 | Удалённые вложения и ошибочные загрузки могут оставаться на диске | File service с cleanup и состоянием файла | Для Nest-загрузки аватара реализованы cleanup временных/ошибочных файлов и безопасный порядок замены; остальные загрузки ещё legacy |
| BUG-001 | Фильтр `admin/students` не разделяет `studying` и `completed` | Фильтр должен точно соответствовать запросу | исправлено в Nest AdminModule; legacy остаётся с characterization и TODO до переключения routing |
| BUG-002 | После обработки profile edit код ищет заявку только среди pending и не находит адресата уведомления; reject-аудит называется `profile_edit_rejectd` | Получать заявку до транзакции либо возвращать результат use case, затем согласованно исправить имя события | временно сохранено в Nest для точной совместимости; покрыто тестом и TODO |
| BOT-001 | `/teacher` передаёт `user.id` вместо `teacher.id` | Бот использует общий teacher use case | при переносе бота |
| BOT-002 | Callback-обработчики не везде повторно проверяют роль и область доступа | Каждый callback проходит ту же policy-проверку, что и HTTP | при переносе бота |

## Решения, которые ещё нужны

1. Целевая СУБД после SQLite: рекомендуется PostgreSQL.
2. Хранилище файлов после локального диска: локальное с абстракцией либо S3-совместимое.
3. Версионирование API: сохранить `/api` или вводить `/api/v2` только для несовместимых контрактов.
4. Доставка уведомлений: transactional outbox и отдельный worker либо синхронная отправка как временная совместимость.
