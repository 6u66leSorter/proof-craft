### 2026-09-22 — Baseline для миграции backend

- **Цель:** подготовить проверяемую исходную точку перед переносом Fastify API на NestJS и Prisma.
- **Сделано:** создан реестр всех 58 маршрутов с доступом, зависимостями, риском и статусом; отдельно зафиксированы решения по совместимости и известные дефекты. Добавлен изолированный characterization-контур на `node:test`: он копирует приложение во временный каталог, запускает Fastify на локальном порту и использует отдельную SQLite-БД.
- **Проверка:** число маршрутов в реестре совпадает с регистрациями Fastify — 58; `npm test` — 5 успешных тестов и 3 целевых TODO; `npm run lint` и `npm run build` прошли.
- **Вывод:** production-код и локальная БД не изменены. Baseline подтверждает три legacy-дефекта: публичность неодобренных работ, доступ преподавателя ко всем активным чатам и неточный фильтр статуса учеников.
- **Следующий шаг:** расширить контрактный набор на авторизацию и права файлов, затем создать минимальный NestJS-каркас с `/health`.

### 2026-09-20 — Фотография ученика видна преподавателю, администратору и гостю

- **Цель:** аватар, загруженный учеником, нигде, кроме его собственного экрана, не показывался.
- **Сделано:** в API добавлены `sendStudentAvatar`, проверка доступа `canUserViewStudentProfile`, endpoint'ы `/api/students/:id/avatar` и `/api/guest/students/:id/avatar`; `has_avatar` добавлен в ответы списка и профиля ученика для администратора, преподавателя (включая дашборд «Проверить») и гостя. На фронтенде появились `getStudentAvatarUrl`, `getGuestStudentAvatarUrl` и общий `studentAvatarImg`; фото подставляется в круги списков учеников у преподавателя и администратора, в шапки профиля ученика у преподавателя, администратора и гостя и в карточку витрины. Без аватара оформление не меняется.
- **Проверка:** `npm run lint` и `npm run build`. Матрица доступа на локальном API: преподаватель ученика, администратор и сам ученик — `200`; чужой преподаватель и посторонний ученик — `403`; ученик вне витрины по гостевому адресу — `404`; ученик без аватара — `404`. Заголовки гостевого ответа: `image/jpeg`, `public, max-age=3600`. Визуальная проверка в браузере не выполнялась: в локальной копии базы записи об аватарах есть, а самих файлов в `data/uploads` нет.
- **Вывод:** профиль ученика рисуют четыре независимые функции (`renderStudent`, `renderTeacherStudent`, `renderAdminStudentProfile`, `renderGuestStudent`), и правку внешнего вида профиля нужно вносить во все.
- **Следующий шаг:** проверить экраны с настоящими аватарами и решить, стоит ли оставлять демонстрационное фото постороннего человека как заглушку для учеников без аватара.

### 2026-09-20 — Просмотр фотографий работ

- **Цель:** в гостевой витрине работа показывалась списком кнопок «Открыть фото», сами снимки не отображались; открытие файла в WebView вело к скачиванию.
- **Сделано:** лента снимков вынесена в общие `homeworkPhotoItems` и `renderHomeworkPhotoStrip` и подключена в гостевом экране, где её не было. Добавлен просмотрщик поверх экрана: оригинал целиком, счётчик, листание стрелками, свайпом и клавиатурой, закрытие по Escape, крестику и фону. Кнопки открытия файла остались только для видео и документов. В `ICO` добавлен `forward`; `polishScreen` больше не затирает заданный вручную `aria-label`.
- **Проверка:** `npm run lint` и `npm run build`; гостевые endpoint'ы отдают превью и оригинал (`200`, JPEG). Визуально проверено вручную в локальной копии с боевыми данными.
- **Вывод:** карусель существовала только в `renderHwView`; гостевой экран рендерится отдельной функцией, и правки экрана работы нужно вносить в обе.
- **Следующий шаг:** `bot/dbBackup.js` копирует базу без WAL — бэкап перед деплоем неполный.

### 2026-09-20 — Выкатка накопившихся изменений на production

- **Цель:** развернуть на сервере версию с входом через сайт, комментариями к ДЗ и конфиденциальной обратной связью; прод оставался на коде начала сентября.
- **Сделано:** восстановлена связь сервера с пересозданным репозиторием (deploy key под отдельным алиасом SSH, `reset --hard origin/main`); в `ecosystem.config.cjs` добавлена передача `TG_WEBAPP_AUTH`, `TELEGRAM_BOT_USERNAME`, `VK_APP_ID`, `VK_APP_SECRET`, `MAX_HOMEWORK_UPLOAD_MB`, `CHAT_ENABLED` в процесс API; в серверный `.env` добавлено имя бота. Миграции досоздали пять таблиц и `students.about_me`.
- **Проверка:** путь миграции заранее прогнан локально на копии боевой базы — данные не пострадали, таблиц стало 19. После деплоя проверены окружение процесса через `/proc`, `pm2 status`, health API и вход в Mini App.
- **Вывод:** до этой выкатки API принимал запросы от имени любого `telegram_id` без подписи Telegram — переменная строгого режима не доходила до процесса. Проверять такие вещи нужно по фактическому окружению процесса, а не по содержимому `.env`.
